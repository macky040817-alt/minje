# Week 5 WiL

## 배운 내용
- 컴포넌트 → 우리가 화면을 나눈 단위
- 카드 → 화면에서 정보를 한 묶음으로 나눈 것
ex. 첫번째, 두번째 카드 → (props) → video카드 (=틀) (받은 내용을 어느 자리에 보여줄지를 정해줌)
부모 컴포넌트 에서 자식 컴포넌트로 : props로 구현한다.

- 배열 → map → 여러가지 카드로 표현 가능하다.

- 필터칩 : 목록을 통해 보고 싶은 범위를 고르게 해준다.
   * 카드는 정보를 묶어주고, 필터칩은 볼 후보를 좁혀준다.

- 클릭 event 를 통해서 필터를 고르고, state (지난주에 배운 usestate) 를 통해서 선택을 기억하게 해준다.
- 카드 (component, props) → 필터칩 (event, state) → 상태 변경 (event, state)
- API : 프로그램끼리 기능/정보를 주고받는 약속이다.
ex. frontend <-> backend (요청/응답)

- 기다리는 동안 보여주는 화면 : skeleton (없으면 지금 되고 있는건지 우리가 알 수 없다.)

- 결과없음과 오류는 다르다.

- 모달 : 보던 화면 위에서 한 가지 작업에 집중하게 해준다. (창 안에서 작업을 이어간다.)
ex. 공유버튼 / 열기, 작업, 닫고 돌아가기까지 모두 고려해야한다.

- 접기,펼치기 (disclosure) : 같은 자리에 정보를 더 보여준다.
ex. 설명의 더보기, 간략히


## 직접 해본 것
- 평소 자주 사용하는 유튜브의 필터칩을 중심으로 UI가 어떻게 동작하는지 살펴보았다. 
- 영상 목록 위에 있는 필터칩에서 '전체'가 아닌 다른 항목을 선택하면 선택된 버튼의 모양이 바뀌고, 아래에 표시되는 영상 목록도 달라지는 것을 확인했다. 
- 이를 이번 주에 배운 개념과 연결해 보니, 버튼을 클릭하는 것은 Event이고 현재 선택한 항목을 기억하는 것은 State의 역할이라는 것을 이해할 수 있었다. 
- React로 직접 구현한다면 지난주에 배운 useState를 활용해 선택한 항목을 관리하고, 그 값에 따라 보여주는 카드 목록을 변경할 수 있을 것이라고 생각했다.

## 느낀 점
- 이전에는 유튜브를 사용하면서 필터칩이나 영상 카드가 어떤 방식으로 구성되는지 생각해 본 적이 없었다. 하지만 이번 주에 배운 내용을 바탕으로 살펴보니 단순히 버튼 하나를 누르는 동작에도 여러 개념이 연결되어 있다는 것을 알게 되었다. 
- 특히 필터칩은 버튼의 선택 상태만 바꾸는 것이 아니라 사용자가 원하는 영상을 더 쉽게 찾도록 도와준다는 점에서 편리한 UI라고 느꼈다. 
- 앞으로 다른 웹사이트를 사용할 때도 화면에 보이는 기능이 어떤 컴포넌트로 나뉘고, 어떤 상태를 관리하는지 생각해 보고 싶다.
